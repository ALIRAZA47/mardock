MarDock collects nothing. A dock doesn't need your data, so it's built so that it can't reach it. Settings ▸ Privacy & Security shows all of this live, read from macOS.

The dock

  • App Sandbox: the dock can't read your files or other apps' data, except files you pick yourself in an Open or Save panel and folders you add to the dock.
  • No network: the dock has no network entitlement, so macOS blocks every connection.
  • Hardened Runtime, with no exceptions, on every executable.
  • No third-party code: pure Swift, AppKit and Core Animation.

The helper

The sandbox rightly stops an app from quitting other apps or changing the macOS Dock. A tiny helper does those few things and nothing else. It only accepts connections from code matching this exact app's signature, and every request is validated: it has no way to run a command, open a path it's given, or write an arbitrary preference.

With Accessibility allowed, it also reads the macOS Dock's badges, the titles of minimized windows, and the New and Open commands in an app's File menu when you double-click it, and it does what you click.

Permissions

PermissionWhen MarDock uses it
AccessibilityOnly for badges, minimized windows and apps' own commands, if you use them.
Screen RecordingOnly for window previews, if you turn them on.
AutomationOnly for Finder, the first time you choose Empty Trash. The sandbox lets MarDock send that one command and no other.

MarDock never asks for Input Monitoring, Full Disk Access, Contacts, Calendars, Photos, Location, Camera or Microphone.

What it stores

Your settings, what's in your dock and each profile, your themes and shortcuts, the last few apps you used (their names and locations only) and any icons you pick. All of it stays on your Mac, inside MarDock's sandbox container. There are no analytics, no crash reporting, no accounts and no update checks unless you ask.

To remove everything, quit MarDock and delete ~/Library/Containers/io.github.aliraza47.MarDock.

Checked on every build

A security audit runs on every change and fails the build if an entitlement is added, or if any binary imports an API it shouldn't. A self-test then checks the design against the real system: that the sandbox blocks the network, and that the helper refuses anything outside its list. You can run both yourself: see Build from source.

In the app, Verify App Integrity re-checks the signatures of the app and its helper.

The full detail is in SECURITY.md and PRIVACY.md. Report a security problem through private vulnerability reporting, not a public issue.
